# Plan 2 — Audio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Live SDS200 network audio. An RTSP/RTP client receives the scanner's G.711 µ-law stream, decodes it to 16-bit PCM, and plays it on the Mac. A WAV writer records it. The session keeps itself alive, always tears down cleanly, and recovers from dropouts. A `noctule listen` command proves all of this against the real scanner.

**Architecture:** Pure protocol pieces live in `NoctuleKit/Audio` (Foundation + Network only, builds for iOS): RTSP messages, SDP, RTP packets, µ-law decoding, sequence tracking, WAV writing, `RTSPClient`, `RTPReceiver`, and the `AudioSession` actor. Playback lives in a separate target, `NoctuleAudioPlayback` (AVFAudio), so the core stays UI- and device-free. `AudioSession` emits an `AsyncStream<AudioChunk>` stamped with arrival time; Plan 3 aligns that with `PSI` hits.

**Mock scanner:** after `noctule listen` is confirmed on real hardware (Task 8), Task 9 builds a mock SDS200 (`NoctuleMockScanner` library plus a `noctule-mock-scanner` executable) that emulates control and audio from a scripted timeline, for development and tests without hardware. The fake RTSP server and RTP sender from Tasks 4 and 6 live in that target from the start.

**Tech Stack:** Swift 6.4, SwiftPM, Swift Testing, Network.framework (TCP for RTSP, UDP for RTP), AVFAudio (playback only). No third-party dependencies.

**Spec:** `docs/specs/2026-11-08-noctule-scan-design.md` (§8 Audio, §8.1 Audio resilience, §9.3 Recording format) and `docs/specs/2026-11-08-sds-remote-protocol.md` (§6 Audio, §8 open items 6–8). Read `AGENTS.md` and `LESSONS.md` first. Plan 1's `ScannerClient` and `UDPTransport` are the patterns to follow: mailbox continuations, bounded waits, and the transient-ICMP policy.

### Where this plan sits

Plan 1 (scanner core) is merged. This is Plan 2 of 4. Out of scope here:
- Splitting audio into one file per transmission on hit boundaries. That's Plan 3, which uses `AudioChunk.receivedAt` against `PSI` arrival times.
- Sleep/quit hooks in the Mac app. That's Plan 4, which calls `AudioSession.stop()`.
- The scanner restart command. It stays a research item (protocol notes §8.8); this plan only offers "power-cycle the scanner" guidance.

## Global Constraints

- RTSP over TCP port `554`. URL `rtsp://<host>/au:scanner.au`. Control URL for SETUP: `Content-Base` + `trackID=1` (on the owner's scanner: `rtsp://<host>/au:scanner.au/trackID=1`).
- SETUP `Transport: RTP/AVP;unicast;client_port=<p>`. PLAY with `Range: npt=0.000-`. Keepalive `GET_PARAMETER` every `15` s. Every request carries `CSeq`, and `Session` after SETUP.
- RTP payload type `0` (PCMU / G.711 µ-law), `8000` Hz, mono.
- WAV: RIFF/WAVE, PCM format tag `1`, `1` channel, `8000` Hz, `16` bits per sample, little-endian (design §9.3). No lossy encoding.
- **Always TEARDOWN** any session that received a `Session` id: on stop, error, cancellation, recovery, and in every test, script, and CLI exit path including SIGINT. A leaked session may wedge the scanner's audio until a power cycle (design §8.1, AGENTS.md).
- **Reconnect cooldown (hardware-proven, 2026-11-08):** the SDS200 audio server hangs, and needs a power cycle, if a new TCP connection to port 554 opens shortly after the previous one closed. A 120 s gap is proven safe; the lower bound is unknown. `RTSPClient.connect()` enforces `reconnectCooldown` (default `120` s) per host through a pluggable cooldown store: in-memory by default, file-backed for the CLI and app so separate processes respect it. Inside the cooldown it throws `RTSPError.cooldown(remaining:)` instead of connecting. Never health-check port 554 with a separate connection. Handshake order is OPTIONS, then DESCRIBE, SETUP, PLAY; headers go `CSeq`, `User-Agent: NoctuleScan`, then the method's own (byte-identical to the proven exchange in protocol notes §6).
- If real-hardware audio wedges, stop and report it. Don't retry in a loop or guess at commands.
- Audio hardware tests are opt-in with `NOCTULE_AUDIO_HARDWARE_TESTS=1`, separate from the control-plane hardware flag. Each run against the owner's scanner opens at most two sessions, sequentially, both torn down.
- NoctuleKit stays iOS-buildable (no AVFAudio, AppKit, or UIKit). Playback goes in `NoctuleAudioPlayback`.
- No recorded radio audio or real-traffic captures in tracked files. The mock uses synthetic audio (tone bursts) and fictional system and talkgroup names.
- No real hosts or addresses in tracked files. Use `config/dev-scanner.env`, which may gain `SCANNER_RTSP_PORT` (default `554`).
- Commit messages end with `Co-Authored-By: <authoring model> <noreply@anthropic.com>` and a `Claude-Session:` line naming the session.

## Review Focus

1. **Stopping at any stage** (after SETUP before PLAY, while streaming, during a keepalive, mid-recovery, from task cancellation, from SIGINT) sends exactly one TEARDOWN for every session id it holds, and never hangs. Pinned in Tasks 5, 6, and 8.
2. **The RTSP server misbehaving:** non-200 status, `454 Session Not Found`, a CSeq mismatch, a TCP close mid-response, or silence past the timeout. The client reports an error state and doesn't hang or crash. Pinned in Tasks 4 and 6.
3. **RTP stream irregularities:** sequence wraparound at 65535, reordering, duplicates, an SSRC change after a scanner restart, packets from the wrong source, and malformed packets (short, version ≠ 2, payload type ≠ 0). Stats are correct, bad packets are dropped and counted, and a new SSRC is accepted after recovery. Pinned in Tasks 2 and 6.
4. **A crash or kill while recording:** the WAV on disk is still playable up to the last flush, because the header sizes are patched on every `flush()`, not only on `close()`. Pinned in Task 3.
5. **Audio stalls while control still works:** the session reports `recovering`, then `failed`, and doesn't silently play nothing. Pinned in Task 6. Whether silence alone means a stall depends on the Task 5 finding.

Encoded as `METHOD url RTSP/1.0\r\nCSeq: n\r\n<headers>\r\n\r\n`, with headers in the given order and a `User-Agent: NoctuleScan` header always added.

  - `enum RTSPError: Error, Equatable { case malformed(String), unexpectedStatus(Int, String), cseqMismatch(expected: Int, got: Int?), noSession, timeout(method: String), closed }` (shared with Task 4).

### Task 2: RTP packets, µ-law decoding, sequence tracking

**Files:**
- Create: `Sources/NoctuleKit/Audio/RTPPacket.swift`
- Create: `Sources/NoctuleKit/Audio/MuLaw.swift`
- Create: `Sources/NoctuleKit/Audio/RTPSequenceTracker.swift`
- Create: `Tests/NoctuleKitTests/RTPTests.swift`

**Interfaces:**
- Produces:
  - `struct RTPPacket: Sendable, Equatable { var payloadType: UInt8; var marker: Bool; var sequence: UInt16; var timestamp: UInt32; var ssrc: UInt32; var payload: Data; init(parsing: Data) throws }`. It requires version `2` and at least 12 bytes. It skips `4 × CSRC count` bytes and the header extension (if the X bit is set: 4-byte header plus `4 × length` words), and removes padding (P bit: the last byte is the pad count). It throws `RTPPacketError.{tooShort, badVersion(UInt8), badPadding, badExtension}`.
  - `enum MuLaw { static func decode(_ byte: UInt8) -> Int16; static func decode(_ bytes: Data) -> [Int16] }`. ITU-T G.711 µ-law with bias 132, using a precomputed 256-entry table.
  - `struct RTPSequenceTracker: Sendable { mutating func observe(_ seq: UInt16) -> Observation; var received: Int; var lost: Int; var duplicates: Int; var reordered: Int; mutating func reset() }` with `enum Observation: Equatable { case first, inOrder, gap(missing: Int), duplicate, reordered }`.
    - Sequence numbers are compared modulo 2^16, using a signed 16-bit distance.
    - A forward jump of 1 is `inOrder`.
    - A forward jump of 2 through 3000 is `gap(missing: d - 1)`.
    - A distance of 0, or a seq already seen in the last 64, is `duplicate`.
    - A backward distance of up to 64 that wasn't seen is `reordered`, and it decrements `lost` by one if it was previously counted missing.
    - Anything larger in either direction is treated as a restart: `first`, which resets the window.

### Task 6: AudioSession: lifecycle, keepalive, decoding, recovery

**Files:**
- Create: `Sources/NoctuleKit/Audio/AudioSession.swift`
- Create: `Sources/NoctuleMockScanner/FakeRTPSender.swift`
- Create: `Tests/NoctuleKitTests/AudioSessionTests.swift`

**Interfaces:**
- Consumes: Tasks 1–5.
- Produces:
  - `struct AudioChunk: Sendable { var samples: [Int16]; var rtpTimestamp: UInt32; var sequence: UInt16; var receivedAt: ContinuousClock.Instant }`
  - `enum AudioSessionState: Sendable, Equatable { case idle, starting, streaming, recovering(attempt: Int), failed(String), stopped }`
  - `struct AudioSessionConfig: Sendable { var keepaliveInterval: Duration = .seconds(15); var stallTimeout: Duration?; var maxRecoveryAttempts: Int = 2; var reconnectCooldown: Duration = .seconds(120); var requestTimeout: Duration = .seconds(3) }`. `stallTimeout` is `nil` when the stream is squelch-gated (per Task 5) and `.seconds(2)` when it's continuous; Task 6 sets the default from Task 5's finding.
  - `actor AudioSession { init(host: String, rtspPort: UInt16 = 554, config: AudioSessionConfig = .init(), makeRTSP: @escaping @Sendable (String, UInt16) -> RTSPClient = { RTSPClient(host: $0, port: $1) }); func start() async throws -> AsyncStream<AudioChunk>; func stop() async; var state: AudioSessionState { get }; var states: AsyncStream<AudioSessionState> { get }; var stats: AudioStats { get } }`
  - `struct AudioStats: Sendable, Equatable { var packets: Int; var lost: Int; var duplicates: Int; var reordered: Int; var droppedMalformed: Int; var droppedWrongSource: Int; var droppedWrongPayloadType: Int; var recoveries: Int }`
- Behavior:
  - `start()`: bind the receiver, connect, DESCRIBE, require payload type 0 (otherwise `failed`), SETUP (`base + control`, receiver port), PLAY, then `streaming`. Start the keepalive loop.
  - Each packet goes through the tracker, then `MuLaw.decode` into a yielded `AudioChunk`. A non-zero payload type is dropped and counted.
  - Recovery triggers:
    - a keepalive failure (timeout, `.closed`, non-2xx including 454);
    - when `stallTimeout != nil`, no packets for `stallTimeout` while `streaming`.
  - Recovery runs `recovering(attempt: n)`: `teardown()` (best effort) and close, wait until the cooldown since that connection closed has elapsed (the state carries the remaining time, `recovering(attempt: n)` plus a published `nextAttemptAt`), then rebuild the RTSP client and receiver and run the start sequence again. It resets the tracker so a new SSRC is accepted. The output stream continues across recoveries. After `maxRecoveryAttempts` failures the state becomes `failed("Scanner audio isn't responding. Power-cycle the scanner if it doesn't recover.")` and the chunk stream finishes.
  - `stop()`: from any state, cancel the loops, `teardown()` once if a session id exists, close, then `stopped`, and finish both streams. Idempotent. Concurrent calls share one teardown.
